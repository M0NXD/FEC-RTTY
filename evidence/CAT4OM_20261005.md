# FEC-RTTY 0.46.1 CAT4OM compatibility check

This is a read-only bench check of the Hamlib NET rigctl TCP path. It does not
identify or depend on the server process name: the endpoint was configured as
`127.0.0.1:4532`, and the test used whatever Hamlib-compatible service was
listening there.

## Observed result

The endpoint returned the standard plain getter replies:

- `f` → one frequency line
- `m` → mode and passband lines
- `t` → one PTT-state line

FEC-RTTY 0.46.1 connected and decoded those replies successfully. The final
bench report showed:

```text
cat_connected=true
cat_fault=false
cat_armed=false
cat_ptt_owned=false
cat_transmitting=false
```

No frequency, mode or PTT write was sent. The regression suite also retains
coverage for Hamlib's extended `+f`, `+m` and `+t` replies, including fragmented
TCP delivery. The CAT4OM service must still be configured and connected to a
radio separately; this check does not validate the physical radio, its CAT
cable or RF transmission.
