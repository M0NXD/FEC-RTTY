## Receiver fix

The v0.45.0 receiver waited for 41 symbols (preamble plus sync) but kept only
26 symbols after an unsuccessful search. Noise at the buffer start also
restricted its search near that noise sample rather than the later burst.

The fixed receiver retains 42 symbols (25 preamble + 16 sync + one symbol
overlap), internally consumes large caller inputs in at most two-symbol
blocks, and scans each newly eligible complete preamble/sync position on its
half-symbol coarse grid. A relative search cursor is adjusted when samples
are discarded, so old noise is not repeatedly rescanned. Existing full-rate
boundary/CFO refinement, FEC/header/CRC validation and EOF timing guard remain.
Every validated new preamble resets sequence tracking for that direct burst,
even when messages are separated by noise instead of silence. Recovery of a
later frame within a burst retains sequence tracking for real missing frames.

An intermediate implementation decoded the failing cases but rescanned too
much retained noise. It was replaced before delivery. The final implementation
processed three seconds of noise in 755 ms (core CTest), 746 ms (GUI CTest),
and 757 ms (deployed packaged audit) on this machine, all below real time.

## Bench exit-code fix

Final audio shutdown/report completion now precedes an explicit exit-code
policy. If an automatic `--send` was requested but never started, failed, or
was cancelled by the timer/window closure, a normal event-loop exit becomes
code 2. A completed send or ordinary non-send GUI closure returns 0. Existing
nonzero startup/report/event-loop codes are preserved. Cancelled drafts and
the error message are retained. The policy is covered independently in core
tests and exercised through actual GUI subprocesses using both audio backends.

## Remaining boundaries

The two confirmed R10 bugs are fixed. R10's separate shutdown/backlog
observation is **not** fixed by this patch: Stop can abandon captured chunks,
and zero queue-overflow drops does not prove that every captured sample was
decoded. The noisy-input runs retain captured/processed counts showing this
distinction, although all test messages decoded correctly. A deliberately
backlogged shutdown/drain regression remains future work.

WinMM lacks PortAudio's equivalent host overflow/underflow flag API; its zero
interruption value is not a host-loss measurement. These are deterministic
noise/virtual-cable tests, not RF fading/interference or real-radio acceptance.
Independent simultaneous paths, long unrelated sound-card clock drift,
USB-unplug recovery, CAT/PTT/audio-level/ALC operation, optional Hamlib and
public redistribution/licensing review remain unverified. Direct text still
has no ACK or delivery guarantee. The 0.1 Hz tuning fields express control
precision, not spectral/audio-clock accuracy.
