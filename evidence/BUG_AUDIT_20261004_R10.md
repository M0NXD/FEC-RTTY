## Confirmed findings

### P1: valid bursts following background noise are not acquired

Locations: `source/src/reliable_receiver.cpp:135`, `:182`, `:243`.

The receiver now waits for a complete 25-symbol preamble plus 16-symbol sync,
but failed-search trimming retains only 26 symbols and the initial search
examines at most eight symbols beyond the first above-threshold sample.
Background noise keeps that first sample at the beginning of the buffer.
Consequently the valid acquisition field can be trimmed before its complete
sync is searched. This affects normal 2048-sample live callbacks, not just
large one-shot inputs. Arbitrary large inputs also need a properly bounded
sliding search or internal chunking rather than searching only their beginning.

Deterministic reproduction: transmit `PREFIX TEST`, prepend one second of
channel-generated background noise (noise parameter 0.02, seed 901), then
feed `ReliableReceiver::push` and `finish`. The modem burst itself may be
clean or have channel noise 0.02 (seed 902).

| Input | Block sizes (samples) | Exact text | Valid frames / CRC failures |
|---|---|---|---|
| Clean burst | 2048, 48000, whole input | Yes at all three | 2 / 0 |
| One-second silent prefix, clean burst | 2048, 48000, whole input | Yes at all three | 2 / 0 |
| One-second noisy prefix, clean burst | 2048, 48000, whole input | No at all three | 0 / 0 |
| One-second noisy prefix, noisy burst | 2048, 48000, whole input | No at all three | 0 / 0 |

Also reproduced through real modem audio on WinMM RX 0/TX 1 (names checked
with device enumeration). One second of noise preceded a 0.25-amplitude clean
`PREFIX TEST` burst. Playback succeeded, TX/RX exit codes were 0, and the GUI
waterfall measured the expected tone region (last peak 1523.4375 Hz), but
**zero acquisitions, zero valid frames, and no text** were produced. The GUI
processed all 536576 captured samples, with zero software drops or reported
interruptions; this failure was not caused by a stopped/draining queue.
See `audit-20261004-r10/physical-noisy-prefix-rx.json`.

Recommended fix: preserve enough acquisition-plus-sync history and ensure
every eligible candidate is eventually searched without unbounded work per
callback. Add preceding/continuous noise and large-input regressions. Repeat
the virtual-cable noise-prefix test as well as ordinary bidirectional tests.

### P2: cancelled timed bench transmission returns success

Locations: `source/src/gui_main.cpp:1404–1414`.

Launch the current GUI with a 500-byte `X` message, TX-only WinMM 1,
`--quit-after-send --run-seconds 3 --report PATH`. The timer interrupts TX.
Its report correctly records `tx_success=false`, `tx_error="Transmission
cancelled"`, and the complete retained draft. However, the process exits 0
because it returns the event loop result without checking the final send
outcome. Exit-code-only callers can incorrectly mark that test successful.
See `audit-20261004-r10/timed-cancel.json`.

Recommended fix: after final session/report completion, return nonzero for
an explicitly requested bench send that failed, was interrupted, or did not
start. Preserve ordinary non-send GUI close behavior and retained drafts.
Add automated timer-cancellation and successful-send exit-code checks.

## Shutdown observation, not a reproduced text-loss failure

The worker exits/breaks when `rx_stop_` is set before the backends are closed;
their close functions then clear remaining capture queues. One tight-deadline
two-frame test reported 468992 captured versus 440320 processed samples with
zero reported drops: 28672 samples (about 0.597 seconds) were not processed.
That message still decoded exactly. Three additional nine-second receive
tests all decoded the distinct two-full-frame payload `01234567ABCDEFGH`
exactly, with TX completed before RX exit and zero CRC/gaps/drops. No loss of
message text from shutdown was reproduced in this round.

The stop/drain policy deserves a targeted regression under a deliberately
backlogged consumer; it should either drain captured audio or explicitly
account for abandoned samples. Do not present this observation as a proven
lost-text failure. Reports: `tight-stop-{rx,tx}.json` and
`tight9-trial{1,2,3}-{rx,tx}.json` in `audit-20261004-r10/`.
