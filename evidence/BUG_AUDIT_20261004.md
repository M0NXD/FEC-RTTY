## Confirmed or likely defects found by code review

1. **Audio backend selection is not persisted.** `AppSettings` stores the RX
   and TX IDs but no `audio_backend` field. The GUI restores the IDs while the
   backend combo starts at WinMM, so a saved PortAudio selection can reopen
   with the wrong backend. This is in `source/include/fectty/settings.hpp`
   and `source/src/gui_main.cpp` (`load_settings`/`save_settings`).

2. **Changing a connected radio backend leaves the old connection alive.**
   The radio combo change handler only enables/disables host and port fields;
   it does not disconnect or replace `rig_control_`. The UI can therefore
   show a newly selected backend while the previous backend object remains
   connected. The same UI pattern lets the audio backend/device selectors be
   changed while a session is running; the active stream continues using the
   old selection while the controls show the new one.

3. **Rigctld TCP handling is incomplete for production use.**
   `NetRigctlControl::command` assumes one `send()` writes the whole command
   and only reads a response when a reply pointer is supplied. The current
   setters do not request replies, so real rigctld `RPRT` responses are not
   drained; the existing loopback test intentionally sends no replies and
   does not cover this case. This is not exercised during the safe bench run.

4. **Large-message WinMM TX length is not bounded before the DWORD cast.**
   `WinMmAudioIo::write` converts `samples.size() * sizeof(int16_t)` directly
   to `DWORD`. Extremely large messages could overflow the WinMM buffer
   length. Normal bench messages are far below this limit.

## Follow-up audit after the output-volume control

The current workspace was rebuilt on 2026-10-04 after the output-volume
change:

- `source\build.bat` — passed; CTest 1/1 passed.
- `source\build-gui.bat` — Qt GUI and PortAudio smoke targets built.
- Simulator — `BUG CHECK`, 2 valid frames, 0 CRC failures, 0 sequence gaps.
- Benchmark — all five noise levels passed with 7 valid frames and 0 CRC
  failures at each level.
- WinMM VB-Audio smoke — 141,312 samples, 0 dropped.
- Packaged PortAudio smoke — exact `PORTAUDIO SMOKE`, 425,984 captured, 0
  dropped.
- Packaged GUI — launched with title `FEC-RTTY - M0NXD` and remained
  responsive.

Two further issues are confirmed:

5. **The lowest output-volume settings can suppress the GUI receiver wake-up
   gate.** `MainWindow::receive_worker` requires a chunk peak of at least
   `0.02` before it forwards samples to the receiver. The generated modem
   waveform has an unscaled peak of `0.999969`; with the default modem gain
   `0.5`, output volume at 4% produces a peak of `0.0199994`, just below the
   gate. At 0–4%, a GUI-to-GUI virtual-cable test can therefore remain in
   `SEARCH` even though the selected output is transmitting non-zero audio.
   This is particularly relevant when reducing output to avoid overdriving a
   radio. The normal 100% setting and the existing loopback tests are
   unaffected.

6. **The GUI build directory is not independently runnable after a successful
   build.** `source\build-gui.bat` builds the executables but does not deploy
   Qt, MinGW, or PortAudio DLLs into `source\build-gui`. Running the freshly
   built `fectty-portaudio-smoke.exe` there returned Windows loader status
   `0xC0000135` because imports such as `libportaudio.dll` and
   `libstdc++-6.dll` are absent. The packaged `releases\...\gui` directory
   contains the required runtime and passed the same smoke test, so this is a
   build-tree/developer workflow defect rather than a packaged-release defect.

## Deliberate boundaries

- CAT/PTT and on-air radio commands remain disabled by request.
- The Qt application/organization settings namespace still contains the old
  internal name so existing preferences are not silently moved; visible
  branding is `FEC-RTTY - M0NXD`.

No crash, decode, audio, or build regression was observed in this audit. The
items above are the outstanding fixes recommended before enabling unattended
radio-control operation.
