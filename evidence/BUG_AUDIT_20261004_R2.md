## Findings

### R2-01 — VB-Audio test script does not run under Windows PowerShell 5.1

Severity: medium; reproducible before the test starts.

`tools/test-vb-audio.ps1:70` uses PowerShell 7's ternary expression:

```powershell
Write-Output "Exact text: $($exact ? 'yes' : 'no')"
```

The documented Windows PowerShell invocation fails at parse time with:

```text
Unexpected token '?' in expression or statement.
```

The same script passes under PowerShell 7.6.5. The harness should use an `if` expression compatible with Windows PowerShell 5.1, or explicitly require `pwsh`.

### R2-02 — Internal application identity still uses the old FEC-TTY name

Severity: low/medium; visible title is correct, configuration namespace is stale.

The GUI title is `FEC-RTTY - M0NXD`, but `source/src/gui_main.cpp:870-871` still sets the Qt application and organization names to `FEC-TTY`. The observed settings file is therefore stored under:

```text
%LOCALAPPDATA%\FEC-TTY\FEC-TTY\fectty.ini
```

This is inconsistent with the requested rename and would need a migration path if the namespace is corrected.

### R2-03 — Repeated GUI sends report a false sequence gap

Severity: medium; decoded text is correct, diagnostics are misleading.

`MainWindow::send_message()` creates a new `ModemSession` for every send, resetting the transmit sequence to zero. `ReliableReceiver` retains its previous expected sequence after reacquisition.

Reproduction using the installed VB-Audio cable:

1. Start one receiver for 45 seconds.
2. Send `FIRST` and then `SECOND` as two separate transmissions.

Observed result:

```text
RX: FIRST
RX: SECOND
Frames valid: 2
CRC failures: 0
Sequence gaps: 1
Acquisitions: 2
Reacquisitions: 1
Dropped samples: 0
```

The payload is exact, but the gap count is not a real lost-frame indication for this normal “two messages in one session” case.

### R2-04 — `build-gui.bat` produces a GUI executable that is not standalone runnable

Severity: medium; affects source-build users.

`source/build-gui.bat` builds `source/build-gui/fectty-gui.exe` but does not deploy Qt, MinGW, or PortAudio runtime DLLs. Direct launch of the freshly built executable returned:

```text
exit code -1073741515 (0xC0000135, DLL not found)
```

The packaged `releases/fectty-v0.38-gui-preview-20261004/gui/fectty-gui.exe` launches successfully because the package contains the required runtime files.

### R2-05 — PortAudio device refresh can terminate an active PortAudio session

Severity: medium; static code finding, not triggered through the native GUI in this round.

`PortAudioIo::list_devices()` calls `Pa_Initialize()` and then `Pa_Terminate()` on every device refresh. The GUI calls that function from `enumerate_audio_devices()`, including the Refresh button and backend-selection change path. If a PortAudio session is active, terminating PortAudio from the refresh path can invalidate the active stream. The device enumeration lifecycle should be separated from the active backend instance.
