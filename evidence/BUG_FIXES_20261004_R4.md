## Resolved findings

- GUI transmissions now use one transmitter sequence for the active audio
  session instead of resetting the sequence for every Send action.
- The reliable receiver resets sequence-gap comparison after a genuine new
  burst and can scan the buffered recovery window when adjacent bursts do not
  have a full quiet boundary. Separate and adjacent independent bursts now
  decode without false gaps or lost follow-up frames.
- `build-gui.bat` now runs `windeployqt` and copies the matching MinGW and
  PortAudio DLLs beside the build-tree executables. The build-tree GUI is now
  directly runnable.
- The VB-Audio test helper runs under Windows PowerShell 5.1 as well as
  PowerShell 7 and reports the receiver exit result portably.
- The visible application identity and the Qt settings namespace are now
  `FEC-RTTY`; an existing `FEC-TTY` settings file is migrated into the new
  namespace without deleting the old file.
- The selected audio backend is persisted with the device IDs.
- Audio backend/device refresh controls are disabled during an active audio
  session, and refresh is refused while a session is live.
- Changing the radio backend, host, or port disconnects the previous radio
  connection before the new configuration is shown as ready.
- rigctld commands now handle partial sends, read and validate `RPRT` replies,
  and mark the connection failed when the socket breaks.
- WinMM TX rejects buffers that cannot fit in the API's `DWORD` length field.
- The GUI low-volume wake gate now accepts the supported reduced-output range.
- PortAudio device enumeration shares a lifetime-managed initialization count
  and no longer terminates an active PortAudio session during refresh.
