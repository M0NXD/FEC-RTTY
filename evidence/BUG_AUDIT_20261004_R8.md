# FEC-RTTY whole-project bug audit — R8, 2026-10-04

> Dated development/test record. Statements below apply to the recorded version and test host, not every reader's setup.
> Device IDs are examples; generated artifacts named here are not public downloads.

## Scope and outcome

Audited the canonical `source/` code, standalone headers, build helpers,
regression tests, Qt GUI path, Windows audio backends, settings/WAV/logging,
simulator/impairment helpers, optional rig adapters, documentation, and bench
harnesses. Work started from local commit `13fe6c9`, with a clean worktree.
Historical releases remain unchanged. No remote repository or push was added.

Confirmed findings below are fixed in v0.44.1. The original regression suite,
46 additional audit checks, and Qt text checks pass. Real modem audio was
decoded between visible GUI processes through the installed VB-Audio cable
using both WinMM and PortAudio. This is not a text/network bypass and is not
a claim that every possible bug or radio-hardware configuration is eliminated.

The transmitted mode remains the original single fixed FEC-RTTY profile:
50 baud, 48 kHz, 25-symbol acquisition, 16-column interleaving, rate-1/2 K=7
FEC, and CRC-16. Direct text is plaintext, unaddressed, and linkless. No
encryption, authentication, keys, HELLO/ACK wait, or retry layer was added.
NullRig/CAT/PTT remained disabled in the physical audio tests.

## Confirmed issues fixed

| Area | Finding and correction |
|---|---|
| GUI text | UTF-8 split across an 8-byte frame or timer poll could produce replacement characters. A persistent UTF-8 decoder now retains incomplete sequences, preserves line breaks/tabs, and suppresses binary display controls. Only compatible version-0, flags-0 Text frames enter the text APIs; control/addressed/future-version frames remain inspectable through the frame API. |
| TX memory and stopping | Whole-message audio allocation and blocking playback made long sends expensive and cancellation slow. A frame-at-a-time producer now feeds one continuous output stream with short blocks. WinMM uses a bounded eight-buffer ring; both backends check cancellation. Errors/cancel retain the draft, and success does not erase newer typing. |
| Audio output | Short final buffers could be truncated at device shutdown. WinMM prefills while paused, does not reset successful output, and the GUI emits a 100 ms silent drain tail. Output level is read for each newly queued block, so gain/volume changes work during a send. Invalid IDs/formats fail explicitly. |
| Tuning and UI accuracy | The center-frequency selector did not configure the modem. It now shifts all RX/TX tones and is frozen during a session. The diagnostic label now says frequency offset. Unused PTT lead/tail controls are disabled and clearly explained. |
| Receiver boundary/recovery | Refined sync using nominal rather than acquired tones, inaccurate sample-boundary tie breaking, unreachable broad reacquisition, and missed final-frame CRC accounting were corrected. Adjacent new bursts can recover after damage. Final flush permits at most 60 samples of zero padding for sub-symbol alignment uncertainty, still requiring valid FEC/header/CRC. |
| Receiver noise/CPU | Matching short tails followed by silence caused false acquisitions and long shutdown processing. Acquisition now requires 20 active symbol intervals. The live coarse search uses half-symbol positions and safe 4:1 analysis stride, with full-rate fine refinement/demodulation. Three seconds of deterministic noise took 1,431 ms in the isolated final measurement, with no locks or output. |
| Parsing/persistence | Trailing numeric junk, NaN/Inf, out-of-range fields, and partial settings mutation were rejected. Settings load is transactional and save uses checked temporary-file replacement with full float precision and Unicode paths. Bench runs do not save over operator settings. |
| WAV/logging | Truncated chunks, invalid fmt/RIFF sizes, bogus allocation sizes, PCM inconsistencies, output failures, nonfinite samples, and Unicode paths are checked. Failed WAV loads leave the caller's prior data unchanged. Log close failures are reported. |
| Simulation/test helpers | Frequency and clock arguments had been ignored by the two-station harness; both now alter actual audio. Invalid acquisition/clock-search steps no longer loop forever. Benchmark failure now returns nonzero. The simulator's version comes from CMake. |
| Build/optional adapters | Core build preserves its cached generator and deploys DLLs from its recorded compiler rather than an arbitrary PATH compiler. GUI build supports SDK/toolchain overrides and runs all applicable tests. Removed an unused function found by the strict build. Hamlib repeated connect disconnects first; OmniRig dispatch ownership/error cleanup is corrected; rigctld connection attempts have a bounded socket timeout. |
| Bench harness | Distinct multi-frame payload blocks expose missing/repeated frames; scripts assert exact text and frame/CRC/gap/drop counters. Windows PowerShell 5.1 needs the native child handle retained before exit to obtain a reliable ExitCode; the CLI harness now does so. |

## Diagnostic attempts retained

Earlier JSON/logs are intentionally retained, not all acceptance results.
The first short reverse GUI burst lost its final UTF-8/blank-line frame;
later short-tail false acquisitions could leave receive shutdown busy. The
sample-boundary, acquisition guard, output prefill/drain, and CPU fixes above
addressed those failures. Intermediate search optimizations briefly regressed
EOF WAV/noisy-frame tests; full-rate refinement and the bounded EOF timing
guard restored them. No tests were disabled or expected failures relaxed.

The first Windows PowerShell 5.1 CLI harness run decoded `HELLO` correctly but
returned a failure because the child's ExitCode was null. Retaining its native
handle fixed the harness; the isolated final run above returned 0. Intermediate
tests with overlapping diagnostic audio are not the reduced-level acceptance
measurement. Final results listed above were rerun after corrections.

## Remaining limitations / verification boundaries

- This is a local experimental modem, not a demonstrated bug-free or
  beta-stable on-air product. A sound-card loopback is not a radio-channel test.
- The fixed profile intentionally does not add continuous AFC/timing PLL,
  alternate weak-signal modes, acknowledgements, delivery guarantees, or
  encryption. Small simulated clock/frequency offsets pass; long independent
  clock-drift, fading, collisions, and real RF interference remain on-air gates.
- The current GUI deliberately does not key a radio. Real Hamlib/rigctld/
  OmniRig CAT/PTT, lead/tail timing, radio clipping/ALC levels, and recovery
  after USB-device removal require hardware acceptance. Hamlib could not be
  compiled here because its optional development package is absent.
- Two independent simultaneous audio directions need another cable/router/
  sound card. Both sequential process directions are tested here.
- Qt deployment emits optional Vulkan-header/DX compiler notices on this
  machine. The Widgets GUI, deployed Windows plugin, and runtime tests launch
  successfully without them; this does not validate optional Vulkan/DX paths.
- DNS resolution for rigctld still uses the operating system resolver. Socket
  connect timeout does not promise a total deadline across DNS/all addresses.
- The UI's high-DPI/contrast acceptance is recorded in the earlier visual/scale
  audits; this round checks text behavior and visible runtime launches, not a
  new pixel-by-pixel visual audit on every monitor/Windows theme.
